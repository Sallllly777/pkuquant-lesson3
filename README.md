# 上交所 Level 2 历史回放与模拟交易

任务 1 的可运行原型：使用 `sse50_20260923.zip` 重建逐笔订单簿，在历史行情中提交模拟限价单，并观察排队、部分成交、撤单和账户变化。

**原始 ZIP 只读，不解压、不覆盖、不清洗原文件。** 新增内容仅为程序、测试和 `reports/` 下的验证结果。内存中的适配包括价格转整数分、事件排序和证券筛选。

## 启动

从 Git 仓库克隆后，先在所选 Python 环境运行 `python -m pip install -r requirements.txt`，并将自行取得的 `sse50_20260923.zip` 放在项目根目录。仓库不包含原始行情和生成的报告；这些文件由 `.gitignore` 排除，本地已有文件不会被删除。

不准备行情数据也可以运行单元测试：`python -B -m unittest discover -s tests -v`。

在本文件夹双击 `start.cmd`，待终端显示启动地址后，在浏览器打开：

**http://127.0.0.1:8765**

也可以在 PowerShell 中运行：

```powershell
.\run.ps1 serve
```

如果 PowerShell 阻止脚本运行，使用 `start.cmd`；它只为此次脚本调用指定执行策略，不修改系统的持久配置。

启动脚本会寻找已安装且具有 PyArrow 的 Python。当前电脑已验证 Python 3.12.5 / PyArrow 25.0.1 可用。也可通过 `L2SIM_PYTHON` 指向自己的 Python。其他电脑需要 Python 3.10+ 及 `requirements.txt` 中的依赖，不需要 Node.js 或前端构建。

终端保持运行；关闭终端或按 Ctrl+C 停止服务。程序仅监听本机回环地址，不连接交易账户。单个服务共享一个模拟会话，切换证券并重置会清空该会话订单。浏览器刷新不会重置账户。

## 第一次操作

1. 默认回放证券为 `600036`，时间为 `09:30:05`，现金 100 万元、昨日底仓 1,000 股。可将底仓改成 0 再重置。
2. “填入卖一”后买入 100 股：观察主动吃单。
3. “填入买一”后买入 100 股：观察前方排队量。
4. 将时间推进到 `09:30:07`：本日该例的买一挂单会在 `09:30:06.440` 成交。
5. 买入限价填 `36.74`、数量 100：形成排队订单；撤单后释放冻结资金。
6. 可播放、暂停、按时间戳单步、向未来跳转。回退需要重置，防止利用已观察的未来行情保留账户状态。

“单步”处理同一毫秒内的全部消息，内部仍严格按业务序号逐笔执行。这样不会在一组成交尚未扣减完的中间状态接受人工报单。“播放速度”是每次处理的时间戳组数，不是恒定墙钟时间倍速。

支持切换全部 50 个证券；每个会话只交易一个证券，不是多资产组合账户。长时间向前跳转需要等待回放完成。

## 已实现的规则与范围

按照本数据日期适用的 [《上海证券交易所交易规则（2026 年修订）》](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml) 实现普通 A 股的相关交易约束：

| 项目 | 本系统行为 |
|---|---|
| 交易阶段 | 识别开盘集合竞价、连续竞价、午休、收盘集合竞价、盘后 |
| 限价成交 | 价格优先、同价时间优先；主动吃单按对手挂单价格；允许部分成交 |
| 撤单 | 仅允许可撤时段；开盘锁定段和收盘集合竞价拒绝撤单 |
| 报价 | 0.01 元价格步长；整数分计算；价格边界四舍五入 |
| 数量 | 主板买入整百股；科创板限价单最低 200 股、最高 10 万股；主板最高 100 万股 |
| 价格边界 | 普通主板 10%、科创板 20% 日涨跌幅；连续竞价价格笼子 |
| 账户 | 买单冻结资金、卖单冻结昨日可卖股份；当日买入不可卖出；不允许裸卖空 |
| 到期 | 竞价订单在收盘集合竞价处理后到期并释放冻结资产 |

零股卖出还参考上交所的 [申报数量前端控制通知](https://www.sse.com.cn/lawandrules/guide/stock/jyglywznylc/tz/c/c_20230209_5716007.shtml)：主板零股余额必须整体申报，可以与部分整手合并卖出。例如 299 股可拆为 199 + 100 股，不能拆为 198 + 101 股。

不支持市价单、融资融券、大宗交易、新股无涨跌幅阶段、停复牌、跨日结算、复权、公司行为、手续费税费或券商实盘接入。当前普通证券规则配置依赖“样本为正常交易股票”的研究前提；不能直接套用到任意证券或其他日期。

## 成交模型，务必先理解

这是**历史行情上的无市场冲击模拟**，不能宣称完全复制交易所收到你的新订单后会发生的市场变化。

历史订单簿与模拟账户分离：历史流始终按原始成交和撤单推进。模拟订单不改写历史成交，也不把后续市场反应重新生成一遍。

| 成交标记 | 推演方法 |
|---|---|
| `TAKER_VISIBLE_BOOK` | 以此刻可见订单逐价、逐笔吃单；记录已消耗的历史委托量，防止连续下单重复使用同一份流动性 |
| `MAKER_TAPE_QUEUE` | 根据被动方委托编号确认历史排队顺序；只有更优价及同价在前订单消失后，后续成交才可分配给模拟订单 |
| `MAKER_NEW_RESTING_ORDER` | 后续新增的剩余委托与模拟挂单交叉时，在模拟挂单价成交，并预留该历史委托量 |
| `AUCTION_REFERENCE_PRICE` | 按已发生的集合竞价真实成交价、可见优先级和真实成交量预算推演 |

同一成交事件的数量预算由模拟订单共享，不能让多张模拟单各自重复获得全部成交量。同价订单严格按模拟提交先后分配。撤单会推进队列；仅触价不保证成交。模型默认报单与撤单延迟为零。

集合竞价**没有重新计算包含模拟订单后的反事实均衡价格**，也没有模拟订单改变对手行为的反馈；其结果只适合小订单的历史条件推演。盘后因只有成交、没有对应完整委托队列，**只回放，不提供盘后模拟报单**。不要用大额订单的模拟成交量作为真实可成交承诺。

## 数据口径与质量证据

详见 [数据研究及验证报告](docs/研究与验证.md)。最重要的两点：

- 委托表披露的通常是进入簿中的剩余委托；主动方可能先成交，只有未成交余量才出现。因此历史委托不能重新撮合后，再重复扣减历史成交。
- 快照的整秒时间可能早于其中已包含的成交。快照仅用于离线对照和已知昨收价；**撮合、最新价及盘口全部来自逐笔流**。代码内 `snapshot` 是原始观测，不可作为策略的安全时点行情直接使用。

“订单引用正常”表示引用与数量守恒检查通过，不代表快照逐字段完全对齐，更不代表预测成交与真实未来相同。

## 命令行和 Python 接口

```powershell
.\run.ps1 test
.\run.ps1 demo
.\run.ps1 audit -All
```

指定 Python 时：

```powershell
python -B -m l2sim demo --symbol 600036 --output reports/demo.json
python -B -m l2sim audit --all --output reports/audit_all.json
python -B scripts/snapshot_clock.py
```

自动演示输出主动买入、主动卖出、被动排队成交和撤单；审计命令验证全天全部证券，并记录原始 ZIP 的前后 SHA-256。

```python
from l2sim.data import ArchiveData, parse_time
from l2sim.engine import Replay

source = ArchiveData("sse50_20260923.zip")
sim = Replay(source.load(600036), cash=1_000_000, initial_position=1000)
sim.advance_to(parse_time("09:30:05"))
order = sim.submit("BUY", sim.book.best("BUY") / 100, 100)
sim.advance_to(parse_time("09:30:07"))
print(sim.fills)
print(sim.state())
```

价格参数以元输入，数量以股输入。核心账本使用整数分。`state()` 为当前回放时点状态；数据源对象本身持有全日历史，不应从 `data.events` 偷看未来构造策略。

## 文件结构

- `l2sim/data.py`：ZIP 只读适配、事件归并、业务序号校验。
- `l2sim/book.py`：逐笔委托簿、撤单和历史成交扣减。
- `l2sim/rules.py`：阶段、价格与申报数量约束。
- `l2sim/engine.py`：模拟排队、成交、资金和股份账本。
- `l2sim/server.py`、`dashboard.html`：本机交互交易台。
- `tests/`：规则、排队、数量守恒、T+1、时序边界等回归测试。
- `reports/`：全量审计、演示结果、快照时钟诊断和页面截图。
