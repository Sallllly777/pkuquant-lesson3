# 任务 1：数据研究及验证

## 结论

这批数据足以实现**订单簿历史回放 + 模拟下单成交**。连续竞价的被动委托队列可由逐笔委托和成交重建；无需用十档快照补出不存在的订单。

不能仅凭这批数据构建能够精确预测任意新增订单市场冲击的完整反事实交易所。当前实现保持历史不变，模拟账户叠加在其上，适合作为微观结构研究和策略接口的起点。

## 已验证的数据解释

以下属于对这份数据的经验识别，并非声称供应商已经提供字段字典。

| 字段/取值 | 本系统解释 | 验证方式 |
|---|---|---|
| `ord.OrderKind = 65 (A)` | 新增在簿委托或主动成交后的剩余委托 | 全日引用及数量守恒 |
| `ord.OrderKind = 68 (D)` | 删除剩余委托 | 删除量等于当时剩余量 |
| `ord.OrderKind = 83 (S)` | 交易状态事件 | 不进入价格队列 |
| `ord.FunctionCode = 66 / 83` | 买 / 卖 | 成交买卖编号与被动队列一致 |
| `ord.FunctionCode = I/O/J/C/V` | 阶段状态标记 | 各证券各 5 条；不当普通订单 |
| `(Channel, OrderOriNo)` | 单证券历史委托键 | 成交 `BidOrder/AskOrder` 与之关联 |
| `BizIndex` | 通道内委托和成交的共同业务顺序 | 同时点先按序号处理；拒绝重复、逆序 |
| `exe.BSFlag = 66 / 83` | 主动买 / 主动卖 | 被动侧的订单编号总能找到 |
| `exe.BSFlag = 0` | 集合竞价成交 | 同时扣减已在簿的买卖双方 |
| `exe.Channel = 2301` | 本数据盘后成交流 | 与竞价委托簿分离 |

状态阶段语义和通道用途仍需供应商数据字典最终确认。系统遇到未知代码或被动方引用异常，会禁止继续模拟成交，取消未完成模拟单并释放冻结资产，而不是默默估算补齐。

单证券按 `(Time, Channel, BizIndex)` 排序；该日每个证券的普通逐笔流只使用一个通道。程序拒绝尚无明确跨通道排序规则的单证券输入。快照没有业务序号，同时间戳安排在逐笔事件之后，仅用于诊断。

## 快照与逐笔时钟不完全一致

如果机械地用快照的标称整秒时间对齐逐笔簿，连续竞价共有 236,581 个快照；买卖一价格同时相等的有 204,245 个（约 86.33%）；买卖十档价格及数量全部相等的有 67,480 个（约 28.52%）。**这些结果不能称为快照完全复现。**

进一步用 `AccVolume` 与逐笔累计成交量对应，发现部分快照包含标称时间之后的成交：

| 证券 | 可对应快照 | 含标称时间之后成交的快照 | 已包含成交最晚超前量 |
|---|---:|---:|---:|
| 600036 | 4,738 | 2,290 | 450 毫秒 |
| 600183 | 4,740 | 4,445 | 950 毫秒 |
| 688008 | 4,740 | 3,859 | 960 毫秒 |

例如 `600036` 的 `09:30:00.000` 快照已经包含 `09:30:00.440` 的成交。该证据说明不能在 `09:30:00.000` 用此快照撮合策略订单；它不意味着可以给所有快照统一加某个固定延迟。

诊断脚本 `scripts/snapshot_clock.py` 与结果 `reports/snapshot_clock.json` 可复现上述观察。为避免未来信息，模拟器不拿快照盘口补簿，不按快照价格决定成交。剩余快照差异仍需要完整供应商时钟/生成机制说明，未强行宣称全部已解释。

## 验证范围与后续方向

自动化测试覆盖时间编码、价格精度、主板/科创板报单数量、零股、价格笼子边界、T+1、资金股份守恒、同价 FIFO、价格优先、同笔成交共享预算、不可重复吃单、集合竞价撤单限制、收盘成交先于到期、异常数据停止成交，以及不提前读取未来流动性。

尚未实现手续费税费、通信延迟、随机排队误差、市场冲击、多证券统一组合、跨日持仓结算、临时停牌及无涨跌幅股票配置。集合竞价沿用观测成交价，不是重新求解反事实均衡；盘后只能回放。因此本阶段不输出策略收益优劣结论。

规则版本依据 [上交所 2026 年交易规则及实施通知](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)。盘后范围变更依据 [上交所修订说明](https://www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20260424_10816474.shtml)。数据代码的经验识别与上述正式交易规则分开维护。
